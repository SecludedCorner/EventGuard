# Changelog

## Unreleased — 0.1.0 candidate preparation

This is a draft for review. No release or version tag has been created.

- Local Windows CLI, Web and optional GUI share persisted events and explicit monitor controls.
- Saved metadata investigations include a bounded related-event timeline, evidence gaps and validated saved diagnostic provenance. Reading a case does not query the host, invoke a model or ACK delivery.
- Bounded Codex delivery has historical single-synthetic-event receive → query → saved metadata result → ACK and natural process-exit evidence. This does not demonstrate waking an existing desktop chat or native diagnosis by the candidate package.
- Owned Windows process Jobs, recovery, source freshness and finite storage keep unknown, partial and failed observations visible.
- Listener baseline validation now preserves bounded fixed error classifications and rejects count mismatches within each TCP/UDP and IPv4/IPv6 table.
- Candidate packaging uses committed files only, records file hashes and checks reproducible archive bytes. Runtime, credentials, local attachments and Git history are excluded.
- Verification rejects empty discovery, early cancellation and mismatched executed/expected test counts; a clean worker exit alone cannot approve a partial suite.

Known limits: native listener identity coverage remains partial in the retained observation; its 111 missing rows are unexplained. Linux native collection, 24-hour production use, reboot recovery, existing desktop-chat wake-up and comparative EDR performance are not accepted. Optional MCP dependencies are not bundled or installed automatically.

Exact candidate SHA, test scope, skips and artifact digests belong to the candidate evidence and [preparation record](docs/RELEASE_PREPARATION.md), not to an assumed final tag.

# EventGuard 產品目標

更新：2026-10-24。以本輪使用者決定為準。

EventGuard 是本機程式。它自行採集、比對規則、保存事件、顯示結果。正常運作不呼叫模型。

## 必做功能

1. CLI 與本機 Web 列出事件。可依嚴重度、來源及處置狀態篩選。
2. `config/rules.json` 可設定規則。提供五條預設規則。
3. 可查看事件詳情。保存新增、已讀、已處理、忽略四種狀態。
4. 顯示七來源的最後採集時間、結果、原因與建議。
5. 新高嚴重度事件顯示本機通知。通知去重。不呼叫模型。
6. `eventguard run` 啟動採集、Web 與通知。可前景執行。按 Ctrl+C 停止。
7. 普通程式追蹤公告與靜態適用性。重要變化才進原事件佇列。不讓模型定時讀網站。

本批公告能力的操作、處理表、限制及待批准項目見 [ADVISORY_TRACKER](ADVISORY_TRACKER.md)。正式背景與真模型驗收未啟用。原 dot 追蹤不變。

處置狀態與投遞 ACK 分開。已讀或已處理不會自動 ACK。未知與拒讀不代表安全。

## 選配

- Codex MCP 接線。
- 閒置喚醒 agent。
- 開機自啟。

| 選配 | 收益 | 成本與限制 |
| --- | --- | --- |
| Codex MCP | 人類與agent操作同一App與狀態 | 需客戶端連線及選配SDK。斷線不關App。工具載入不代表閒置喚醒；本聊天十工具已驗，不保證其他客戶端熱載入 |
| 閒置喚醒 | 重要事件可自動交短期agent | 有事件才用模型。計入固定日預算；未知退出需對帳。桌面queue仍待真驗，優先既有有限CLI通路 |
| 開機自啟 | 登入後可恢復普通監看程序 | 增加啟動項維護及長期資源成本。須另行批准；本輪不建立。重開機與soak未驗 |

以上三項不阻擋產品開發、驗收或使用。只完成已批准的專用MCP接線與無模型介面；不自行啟動模型或自啟。不得再次要求重開 Codex、proxy 探測、登入任務或任何排程。

## 工作方式

- 使用中文短句。
- 先完成功能。再統一測試。
- 測試資料與真實來源分開。
- 只有新功能可新增對應 reports 證據。
- 文件與功能放在同一個 commit。不做文件單獨提交。
- 保留既有資料、研究與附件。不 reset、clean 或推送。

## 完成條件

同一筆事件可在 CLI 與 Web 查到。篩選作用於全庫。處置狀態在程式重開後仍保留。規則變更在下一輪生效。來源拒讀顯示原因。通知不因重開而重複。空佇列不呼叫模型。停止後核實本工具程序退出。

24 小時測試與真實狀態注入未完成。不得稱為全天候保證。一般權限、唯讀採集及標準庫界線仍有效。

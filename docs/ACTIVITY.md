# 情報中心內的操作紀錄

EventGuard 的方向是本機資安情報中心：保存來源觀察、事件與查證結果，讓人類與 agent 使用相同能力，並在產品內看得到操作。外部漏洞情報匯入、跨主機整合與自動處置仍未實作；不能把這個方向當成已完成能力。

## 看得到什麼

GUI「操作紀錄」頁籤顯示最近操作的入口（人類視窗／Agent工具）、動作、開始時間、執行中／已完成／受阻／失敗、耗時與固定結果碼。操作先記錄running才執行，結束後更新同一筆，因此MCP執行中的工作可由GUI刷新看見。CLI可讀：

```powershell
py -3.13 -B scripts/eventguard.py activity --namespace live --limit 100
```

共享MCP的`activity(limit)`讀同一份紀錄。查看歷史與GUI自動刷新不再寫入一筆「查看歷史」，避免無事件時產生紀錄洪水或模型輪詢。

涵蓋共享operator MCP的操作，以及GUI的開始、暫停、事件查看、接收開關與自動agent開關。這不是對所有程式的監控，也不收集聊天思考、提示、完整命令列、檔案編輯史或其他工具的活動。舊的事件綁定三工具CLI驗收adapter不是共享operator，不能據此宣稱其每一步已列在此頁。

## 保存與限制

- 位置：本機忽略的`data/activity.sqlite3`，不提交Git。
- 最多256筆；只輪替完成／失敗／受阻／已確認owner退出的中斷紀錄，保留仍執行中的操作。最多32筆同時執行，資料庫頁面上限2MiB。
- 只保存固定動作、入口、scope、時間與結果碼；目標ID僅存短hash，不保存事件內容、原始參數、提示、路徑或原始例外。
- 入口標籤是程式產生的來源識別，不是帳戶認證或防同使用者竄改的稽核保證。
- 執行前無法保存紀錄時，一般操作明確拒絕。**暫停、撤回接收權限及停用自動agent除外**：不能因紀錄故障而阻止停止；停止仍執行並回傳activity_warning。
- 執行已完成但收尾無法落盤時，回`activity_completion_not_persisted`及`operation_may_have_completed=true`，禁止自動重試。應核對原操作的事件／退出證據。
- owner PID加建立時間確認已退出而缺少結束回條，顯示「中斷，結果未確認」；不能改成成功。owner不可確認就維持未確認執行狀態，不猜測結束。

正式MCP需人類開啟接收權限；註冊本身不啟動監看或模型。執行日常操作的記錄不等於漏洞已修補；ACK只代表收到。既有視窗不熱更新，新增頁籤於下次正常開啟時載入。

operator可接受多client；狀態變更另用短期操作鎖，busy會顯示受阻，不自動重試。讀取與Stop不被該鎖阻擋；Stop仍核對固定scope及owner，不因其他client正在查證而失去暫停入口。2026-10-23本主聊天已用正式activity工具讀到本輪capabilities／overview的完成紀錄；這是同表讀取證據，沒有宣稱已操作或熱更新既有GUI視窗。

# 本機頁面操作與驗收界線

在專案目錄執行：

```powershell
.\EventGuard.cmd run
```

開啟程式顯示的本機網址。預設為 `http://127.0.0.1:8765`。
若該埠已有其他程式，使用 `run --port 8877`。不要停止其他程式來讓出埠。
`run` 即開始採集。沒有另設瀏覽器「開始」按鈕。關閉瀏覽器不會停止程式。

## 操作

1. 按「來源狀態」。核對七來源的最後成功、最後採集、目前新鮮度、失敗原因及建議。
2. 按「暫停採集」。等待頁首顯示「已暫停」。此時仍可讀事件與保存人的處置。
3. 在事件頁選嚴重度、來源及處置狀態，按「篩選」，再按該事件的「查看」。
4. 按「已讀」或「已處理」。重新整理後可再依處置狀態找回。
5. 按「恢復採集」。它只恢復本機採集，不啟動 agent，不刪 pending，也不 ACK。
6. 按「停止監看與網頁」。頁面顯示已提出停止要求，並停止刷新。
7. 在執行終端核對最後退出結果。停止要求不等於程序已退出。

再次執行同一命令使用原資料目錄。事件與人類處置狀態會保留。
已處理、忽略及投遞 ACK 是不同狀態。它們不代表系統已修補或主機安全。
來源最後成功是歷史時間。它不能把目前的拒讀、未知或過期改成成功。

頁面使用合成來源時會顯示「合成驗收資料」。這不是主機實測結果。
CLI 與 Web 使用同一保存資料。重新整理頁面不會要求重新掃描來源。

```powershell
.\EventGuard.cmd sources list
.\EventGuard.cmd events list --source listeners --status handled
.\EventGuard.cmd events detail --event-id <ID>
```

## 本版驗收

本版使用隔離 test namespace、真 CLI 主入口、真應用後端及 Windows 私有 Job。
在真瀏覽器選取篩選、點擊詳情、已讀、已處理、暫停、恢復及停止。
重新整理及整個應用重啟後，核對同一事件 ID、handled 及 pending。
也核對七來源的合成拒讀／未知、原因與最後成功時間。

開始由正式 `run` 入口完成；沒有冒稱點擊一個不存在的開始按鈕。
瀏覽器操作、實際程式退出、SQLite 與唯讀 CLI 證據分開保存。
詳細命令、時間、範圍及原始失敗只見 [EVIDENCE](EVIDENCE.md)。

此驗收沒有主機來源掃描、正式背景啟用、真模型、排程、24 小時或重開機。
通知圖示在目前驗證環境不可用；不能聲稱使用者已看到 Windows 系統通知。

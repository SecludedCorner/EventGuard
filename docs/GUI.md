# EventGuard 視窗操作

## 查看保存錯誤計數

「七個來源」向右捲動可見「保存錯誤計數（非安全判定）」：分列錯誤總數、最多64筆保留明細及核對後的固定stage／status計數。最多顯示3組，另有組數提示；缺摘要或數字矛盾顯示全量分類未知。錯誤明細未保留不代表沒有錯誤，分類計數已核對不代表來源完整、資料已認證或主機安全；查看不採集、不呼叫模型、不ACK。

## 查看事件的 agent 預設政策條件

選取事件，在詳情中的「Agent 預設政策條件」查看符合或不符合的原因。預設只選 high／critical；warning 線索仍保存供調查。人工標記已處理／忽略會列為政策排除，與投遞 ACK 及修復保持獨立。

這是讀取詳情時的預設條件快照；自訂 dispatcher 政策、重試時間／lease、接收權限與啟動同意需另核對。符合不代表 agent 已被喚醒、收到事件或防守成功。資料缺失、格式或事件 ID 不符顯示未知；查看不會啟動模型、修改門檻或 ACK。

雙擊根目錄 `EventGuard.cmd`，不需要終端指令。需要既有 Python 3.13 與 tkinter；缺少時回報，不下載安裝。`Start-EventGuard.cmd` 會開啟視窗並送出開始要求。

| 操作 | 實際效果 |
| --- | --- |
| 開始 | 啟動同一耐久 Monitor，無每日或一小時採集期限；若另行保存自動 agent 選擇，才同時啟動純程式待命 |
| 暫停 | 先耐久保存 disabled，再合作停止本工具查詢；事件與 baseline 留原位置 |
| 關閉視窗 | 最小化到工作列，應用與監看繼續；可從工作列恢復 |
| 應用程式 → 暫停並結束 | 確認本工具 host／子程序退出後才離開；未知時保留視窗與錯誤 |
| 七個來源 | 顯示筆數、可見性、觀察時間、新鮮度及固定拒讀原因；只讀保存觀察 |
| 事件與內容 | 選取後先看觀察事實、未知與限制、建議的唯讀查證；展開勾選才顯示原始 JSON |
| 建立／更新保存調查 | 明確保存所選事件與既有 metadata 的調查快照；不採集、不呼叫模型、不 ACK，完成後讀回 |
| 新增／已讀／已處理／忽略 | 保存人的決定及操作歷程，完成後讀回；與投遞ACK獨立，不代表修復或安全 |
| 備份已保存處置歷程 | 明確備份本安裝 live 歷程到 reports，自動命名且不覆寫；不清理、不還原、不釋放容量 |
| 核對剛才備份 | 本視窗取得成功備份回條後啟用，明確點擊才核對本程序最後寫出的那一份；結果在「備份核對」分頁 |
| 嚴重度／接收／人工狀態篩選 | 三者取交集，只篩目前載入的最多100件，顯示符合／載入／儲存總數及截斷；清除篩選還原三項，不改事件 |
| 允許 agent 接收事件 | 保存本安裝接收開關；預設關閉；開啟也不啟動模型或自動連線 |
| 操作紀錄 | 顯示共享MCP及GUI操作的開始、執行中、結果與耗時；不記錄聊天思考或完整命令列 |
| 自動交給專用 agent | 另外明示模型授權；選擇既有原生 codex.exe，有 pending 才啟動短期任務，沒有事件不呼叫模型 |

按鈕與背景 worker 分開，來源慢查詢不阻塞 Tk 畫面。狀態每五秒由普通程式讀取，不由模型輪詢。未知、部分可讀、拒讀與過期不等於安全。
「自動 agent 設定」位於獨立分頁，避免長設定列擠掉事件；接收開關與狀態仍在主畫面。預設1080×760與最小850×620已做實際Tk幾何及Tab路徑驗證；縮小視窗會讓已選事件回到可見範圍。這不是真人操作、原生鍵盤或Web200%驗收。
狀態讀取失敗時，來源與事件內容不沿用舊資料，筆數及設定狀態明示未知，保存調查暫停；重新讀取成功後可再操作。讀取失敗不代表接收權限已撤銷或自動任務已停止。

[操作紀錄](ACTIVITY.md)先保存操作意圖，完成後更新同一筆；可看到Agent工具正在查證或人類正在開始／暫停。紀錄無法保存時一般操作會明確拒絕，暫停仍可執行並提示紀錄失敗。只保留最近有界歷史，不代表所有外部程式活動。

事件時間使用保存的 observed_at。摘要沿用既有 guidance，不觸發查詢、ACK 或處置；首次盤點不等於新攻擊，恢復轉換不等於目前已修復。篩選為零或清單空白不代表沒有事件或主機安全；較早事件仍在本機，可由既有 CLI 查閱。篩選、選取及展開內容都是唯讀；所有名稱與內容仍是不可信資料。這批改善的研究依據見 [採納記錄](SCANNER_LESSONS.md)。

保存調查按鈕只在所選事件詳情已核對且非忙碌時啟用。版本或空間不足會保留原調查與事件；結果未確認時先重新查看，不自動重送保存。調查保存不代表收到事件、已修復或主機安全。
人工狀態按鈕亦要求已核對詳情。若結果未確認，重新點選原狀態會沿用同一操作識別；程式不自動重送，不把人工「已處理」變成ACK。當前狀態按鈕通常停用；仍有未確認要求時可明確重試原要求。

事件清單分列「人工處置」及「接收狀態」：已處理仍可能待接手，已接收也不代表人工已處理。人工狀態必須與已載入事件的保存雜湊及接收狀態相符；缺失、變動或無法核對顯示未知，可選「未知人工狀態」查閱。保存後只讀重載清單及詳情；若新狀態不符合篩選，該列與詳情會移出目前視圖，事件仍保留。

人工狀態保存失敗時，容量不足與「操作紀錄無法建立、尚未執行」分列，保留原資料及pending；備份不會釋放容量。若狀態可能已提交但活動完成紀錄無法保存，畫面維持「結果未確認」，只由人類再次點選原狀態，以同識別核對，不自動重送或宣稱未保存。

人工狀態列持續顯示所選事件的未確認要求，切換事件不串顯。保存動作先把原識別、事件hash、namespace與要求狀態落盤，再執行狀態寫入；只有畫面收到匹配回條後才核對並清除該要求，兩階段都不ACK或重送狀態。

重開後先查看保存歷程與「未確認要求」；已保存的原識別會於詳情讀取時恢復，但不自動執行。明確點選原狀態是核對原要求，不能當作新的決定；如果另一操作者其後改過狀態，原ID重播會保留較新的決定。需要新決定時，先核對舊要求，再明確選狀態。未確認意圖最多128筆，不自動丟棄或到期。

日誌讀取失敗、schema不符、namespace／事件hash／識別衝突時，人工寫入停用，既有詳情仍可閱讀；不能把unknown當成沒有待確認要求。意圖準備尚未確認時，狀態操作不會開始；不要自行刪日誌或換新識別重送。兩真Job／Tk的成功回條丟失、自然退出、同資料重開與原ID核對已有自動化證據，仍不代表真人或原生輸入驗收。

若畫面說「保存回條已收到；待確認要求清理結果未確認」，表示保存回條已經過核對，未知的是要求紀錄清理。原識別在本視窗保留，可明確核對；不自動重送、不把此訊息當成未保存或主機已修復。清理已完成但回條遺失時，重開可能沒有待確認筆數，請先讀目前狀態與保存歷程，不能從零筆推論從未操作。

已保存但未確認的人工要求會保留原事件與收據，即使投遞已ACK也不因TTL、件數或位元組壓力移除；容量上限不變，可能因此拒絕新寫入。明確核對後才恢復原保留政策，不是刪除處置歷程的入口。receiver-finalization對收據的保護與人工要求各自獨立，完成其中一項不會替另一項確認；日誌不明時清理失敗而不自動清空。

### 查看較早事件的人工未確認要求

「查看待確認要求」切換到獨立的唯讀清單，即使原事件已不在最近100件也可找到；同事件多個要求合併一列，每頁最多100件、總範圍最多128件不同事件，按事件ID穩定排序。這是人工保存回條的要求，接收狀態另列，讀取不採集、不呼叫模型或ACK。

以「上一頁／下一頁」換頁；嚴重度、接收及人工篩選只套用目前這一頁，不能把空頁或篩選零列當成沒有要求／主機安全。選事件後，詳情才恢復已驗證的原識別；只有人類明確按原狀態才核對，不自動重送，也不回退較新的決定。

待確認頁是讀取快照，來源／計數更新不會換掉它，頁首會分開標示。核對完成後按「刷新」才重新讀待確認頁、移除已確認列；最後一頁可能變空，可回上一頁。錯頁／namespace／hash或壞資料顯示未知並停用人工寫入，不能當成已清空，可明確重試或返回。

「返回最近事件」恢復原篩選與仍可見的原選取／Tk item焦點；原事件不在最近100件時不補造。讀頁中也能返回，之後晚到的頁不套用到最近模式。上述已有實際Tk＋101件合成SQLite證據，原生鍵盤、真人、Web及真實來源仍各自待驗。

歷程備份含敏感事件／操作識別，僅留本機，勿提交或分享。按鈕不需選取事件，範圍為本安裝目前保存的 live 歷程；忙碌期間停用防止重點。成功回條列出相對 reports 路徑，檔案已同步並讀回核對，但目錄項耐久性未驗、雜湊不是來源認證；不保證歷程完整或可還原。失敗或回條不符顯示未確認，不自動重試／覆寫，原歷程與pending保留。

備份核對只顯示衝突、已存在／缺失計數及前綴／分歧，零衝突不代表來源可信、歷程完整、容量可恢復或可還原。開啟分頁不讀檔；檔案變動／缺失或回條不符會清掉舊成功，新備份未確認時禁用。只記住本次執行最後一份已確認備份，重開應用不會掃描reports或任意私人路徑；需再次明確備份才可在桌面核對。此入口不還原、不清理、不釋放容量、不ACK。

核對結果列出讀取開始／完成UTC區間，計數是區間內的一次資料庫快照，不能證明之後狀態。缺失、無時區、逆序或無法核對的時間顯示未知，不以目前時間補舊結果。

「備份內部轉換」另列相鄰轉換檢查對數及已知衝突；即使身分衝突為0且前綴相符，也可能有內部轉換衝突。沒有可比較相鄰記錄時顯示未觀察，一致也不能證明首筆狀態、缺失歷程或來源真實性。格式或計數無法核對顯示未知。

核對分頁提供捲軸及「返回事件與內容」，保留原事件與篩選，返回不重新讀檔。核對還在進行時也可返回；晚到結果只更新核對分頁，不把畫面切回。進入／返回會設定相應Tk焦點目標，真人及原生鍵盤驗收另列。

已有另存診斷時，摘要分列歷史查證時間／結果、來源狀態、保存列數、截斷與缺口。缺失或身分不符維持未知；當時可讀不代表目前可讀，查無資料不等於恢復。細部觀察及完整 coverage 仍可展開結構化資料核對；查看不會重新查詢。

GUI 使用同一 OperatorAPI／SQLite；沒有另外一套採集、事件或 ACK。監看 child 從建立時在私有 Job，GUI 保留 Job handle；host 同時核對應用 PID＋建立時間，應用意外退出／身分未知時合作停止，不留下無 owner 的持續採集。這是應用生命週期，沒有繞過外部 Job 或啟用服務。

agent 開關不是裝飾：live MCP 的操作每次先查開關，關閉時不回傳事件／來源 metadata、不接收或 ACK；live dispatcher 也不會啟動 agent。人類的 CLI／GUI 操作不受影響；pending／query 仍保留，可由人類接手或稍後重新開放。已經回傳給接收者的資料不能收回。明示 test／synthetic 契約不受此 live 開關改寫。

可選接收者仍須明確連接現有入口：

```text
py -3.13 -B scripts/eventguard_inbox_mcp.py --operator-root . --namespace live --allow-live
```

這是 stdio client 的 command／args，並非啟動模型的指令。沒有自動註冊 MCP、網路 listener 或喚醒目前聊天。畫面會如實顯示「尚未證明 agent 連線或收到事件」。

自動模式是另一個獨立開關，需既有登入、MCP SDK、原生 codex.exe 與當次有效模型授權；步驟見 [接線指南](CONNECT_AGENT.md)。開視窗／刷新不啟動模型。明確按開始才沿用保存的自動選擇；監看已運作時勾自動開關會開始待命。暫停會取消等待與本工具的執行中任務，核對退出後才允許結束。取消自動勾選不停止本機採集。

現行桌面模式不設每日五次 quota，也不讀寫歷史預算帳本。桌面當次 dispatcher 目前預設最多5個任務，達到後顯示 `waiting_task_limit` 並保留 pending；這是單次執行界線，不會因跨日自動恢復。失敗事件不自動重試模型，需查證後在有效授權內明確重試或由人類接手。模型帳戶額度與具體執行授權仍各自適用；應用不因這個單次任務上限而關閉。

登入後自動恢復是另外一次 [背景排程](BACKGROUND.md) 設定，目前未獲批准／建立。GUI 的開始／暫停可以直接使用；不把開啟視窗或有限測試當作實際重開機、長時 soak 或全天候成功。完整當前驗證見 [EVIDENCE](EVIDENCE.md)。

## 桌面合成六任務（真人結果待驗）

使用既有Python 3.13／Tk，在專案目錄明確啟動；每次選新ASCII名稱，既有目錄拒絕覆寫，不要刪舊證據來重用名稱：

```powershell
$desktopUxRun = 'desktop-ux-human-20261029-01'
py -3.13 -B scripts/desktop_ux_acceptance.py --name $desktopUxRun --seconds 900
```

視窗明示「合成固定情境（非主機實測）」，資料固定於準備時間；採集、模型／agent設定及ACK停用。讀寫只在新reports scope，內層data/live僅為合成副本，不是安裝live。最長900秒後合作關閉，也可用「應用程式→暫停並結束」；X仍是最小化。啟動終端Ctrl+C會請求合作退出，父程序保存原Job handle的實際退出／殘留收據；未確認不報成功。

在「六項合成任務」分頁依序操作：

| 任務 | 要觀察／完成的事 |
| --- | --- |
| U1 | 七來源目前拒讀、部分、未知、過期與歷史成功的差異。 |
| U2 | synthetic-ux-listener的事實／未知；能否據此宣稱主機安全。 |
| U3 | 標已讀再已處理，核對人工歷程與接收狀態不同。 |
| U4 | 人工／接收篩選、清除並找回原事件及保存狀態。 |
| U5 | 歷史拒讀／截斷查證，能支持與不能支持的目前結論。 |
| U6 | 備份、核對讀取時間／轉換／未知範圍，返回原事件。 |

請由真實參與者另行記錄步數、秒數、錯誤及結果。程式不自動評分或填結果。結束後可逐任務輸入實測數值，例如U1；下列Read-Host沒有預填成績：

```powershell
py -3.13 -B scripts/desktop_ux_acceptance.py --name $desktopUxRun --record-task U1 --steps (Read-Host '實測步數') --elapsed-seconds (Read-Host '實測秒數') --errors (Read-Host '錯誤數') --outcome (Read-Host 'completed / failed / unresolved')
```

範圍為步數／錯誤0–1000、秒數0–900；缺值、非法值拒絕。tasks.json的六筆初始metrics皆null；每筆輸入獨立保存task-U1.json等，既有檔不覆寫／合併。自報永久明示operator_self_report_unverified及human_participation_verified=false，不能因輸入completed就宣稱真人驗收通過；session-result.json僅是程序收據，participant_results仍null。真人完成率／時間／錯誤仍需實際參與及獨立審閱，不與合法競品環境比較或原生覆蓋混同。

所有runtime／SQLite／任務紀錄僅留reports，不提交或分享私人畫面。

### 重開原合成資料，另存本次收據

先結束原視窗並確認session-result.json的synthetic_session_closed及guardian剩餘程序0，再選新的attempt名稱。`--reopen-from`永遠指向最初建立資料的名稱（上例的$desktopUxRun），不能改指向只有新收據的重開attempt：

```powershell
$desktopUxReopen = 'desktop-ux-human-20261029-02'
py -3.13 -B scripts/desktop_ux_acceptance.py --name $desktopUxReopen --reopen-from $desktopUxRun --seconds 900
```

人工狀態、歷程及保存調查仍讀寫原scope，不複製、重seed或清空DB。這次的ready／exit／guardian、tasks.json與之後明確輸入的task-U*.json留新attempt；記錄重開後任務時，`--name`使用$desktopUxReopen。每個attempt的空白任務計畫不代表舊任務成績遺失，也不會自動繼承或填入真人結果。

# Coverage 缺口分析與最小診斷計畫

版本基準：`fd45578`｜文件日期：2026-10-22｜狀態：唯讀分析，不是權限變更或採集授權。

本文件只依指定驗收摘要與同版本原始碼分析。沒有執行任何原生採集、重跑全機掃描、提權、UAC 操作或程式變更；也沒有重新驗證目前主機狀態。本文匿名化，不包含實機告警內容、事件識別碼、私人路徑或原始證據。

## 1. 先說可確認與不可確認的事

獨立驗收的工程結論是部分原生來源 coverage 不足，整體仍為 BLOCKED。本儲存庫不公布逐來源實機值；下列矩陣只描述程式查詢路徑與待核實問題。任何 denied 都不能當成成功空結果、沒有異常、主機安全或已遭入侵。

不能只憑部分 denied 斷言「所有來源都需要管理員」或「一定是執行隔離造成」。Defender、端點、程序、服務與排程的實作使用 CIM 或系統 provider 型 cmdlet；Startup 與版本主要使用登錄／本機資料夾與檔案 metadata。這是需要分開驗證的路徑，不是實機根因證據。

一般未提升的使用者在不同 Windows 版本、組織政策、provider、命名空間 ACL、來源物件 ACL 與執行 token 下，可能有不同可讀範圍。**非管理員、未提升 token、受限執行環境是不同概念**；即使確認其中一項，也不能推導其他項目。不得以整體提權當成診斷捷徑。

## 2. 來源與權限矩陣

下表的「一般使用者候選可讀範圍」只是待核實的最小查詢目標，不是本環境保證，也不是追加權限建議。

| 來源 | 現有程式查詢路徑 | 一般使用者候選可讀範圍／重要區分 | 原生實測披露 | 仍未知 |
| --- | --- | --- | --- | --- |
| Defender | `Get-MpComputerStatus` | 防護設定 metadata 是否可讀取決於 Defender provider／政策；不能假設查詢一律需管理員或一律可讀 | 不公布主機原生值；按批准範圍另驗證 | cmdlet／provider 拒絕，還是工具啟動上下文、token 或安全政策限制 |
| listeners | `Get-NetTCPConnection`、`Get-NetUDPEndpoint` | 本機端點 metadata 與程序／路徑權限要分開；不需要為判斷綁定範圍探測網路 | 不公布主機原生值；按批准範圍另驗證 | NetTCPIP provider、CIM 存取、政策或執行隔離的實際拒絕位置 |
| processes | `Get-CimInstance` 查 `Win32_Process` 的限定欄位 | 程序基本 metadata、可執行路徑與建立時間不是同一可讀性保證；部分路徑為空應為 unknown，不該等同全來源 denied | 不公布主機原生值；按批准範圍另驗證 | 整個列舉被拒、欄位／物件限制，或執行 token／CIM 路徑問題 |
| services | `Get-CimInstance` 查 `Win32_Service` 的名稱／狀態／啟動模式 | 只讀服務 metadata 與變更服務設定所需權限不同；不能由無變更權推論無讀取權 | 不公布主機原生值；按批准範圍另驗證 | CIM／provider／命名空間或其他政策所限；沒有 ACL 證據可定案 |
| tasks | `Get-ScheduledTask` 的限定 metadata | 任務可見性可受各任務 ACL 影響；未列出、不適用、單項拒讀與來源拒讀要區分 | 不公布主機原生值；按批准範圍另驗證 | provider／整體列舉／特定任務可見性或工具上下文限制 |
| Startup | 登錄 Run／RunOnce 名稱、經本機路徑檢查的 Startup 名稱 | 可選鍵已確認不存在可算完整觀測；只代表列明範圍，不代表完整持久化盤點 | 不公布主機原生值；按批准範圍另驗證 | 其他持久化來源及未涵蓋的使用者／路徑仍不在結論範圍 |
| versions | 明確固定本機檔案的版本 metadata | 能讀一個允許檔案的版本，不代表能讀所有產品版本，也不是漏洞或修補狀態驗證 | 不公布主機原生值；按批准範圍另驗證 | 其他產品／版本、修補與使用情況不可推論 |

即使 Startup／versions 成功，也只能排除「工具完全沒有任何讀取能力」這類過度概括。它們不能單獨證明 CIM provider 正常，也不能把某些成功來源擴張成整機 coverage。

## 3. 原始碼能證明的分類邊界

`collectors/runner.py` 有兩條需要分開的路徑：

1. 啟動查詢子程序時的明確 `PermissionError`，會得到 `denied` 與固定原因碼 `query_launch_access_denied`。
2. 子程序正常回傳 JSON 後，採集腳本內的 `Read-Status` 可能把明確未授權例外、拒絕存取 HRESULT、provider 的 AccessDenied，或 PermissionDenied／SecurityError 類別分類為 denied。

第二條中的 SecurityError 仍可能涵蓋不同安全限制；最終 section 狀態並不攜帶足夠的原始權限證據。因此，同一個 `denied` 不能直接等同「來源 API 必須管理員」或「OS token 被 sandbox 阻擋」。原始碼保留資料最小化是合理的，但要定位缺口，需要額外且經批准的固定代碼／階段證據，而不是公開原始錯誤全文。

來源非零退出、無法解析或輸出讀取錯誤，runner 另列為 error；來源不存在／命令不存在可列 not_applicable。後續分析不要把這些狀態重新混為 denied，也不要用任何無資料情況推論安全。

## 4. Start 5 與 Stop 0 的正確解讀

CLI 將 `partial / denied / unknown / timeout` 或 `healthy=False` 映成 exit code 5。因此，Start 返回 5 與「已完成一次工作但 coverage 降級」相容，**不等同程序崩潰或根本沒有啟動**；仍需對照該次結構化結果與最終狀態才能判定。

Stop 返回 0 只表示停止命令沒有回傳 CLI 錯誤；可能是已成功建立合作停止請求，也可能是當下沒有 owner。它不證明先前的監看仍在執行、不證明查詢已清空，也不表示 coverage 已修好。應核對 `stop_requested / not_running`、對應 instance、最終 `monitoring=false`／owner 釋放及查詢自然結束；狀態過期時維持 unknown。

不要為「讓 Start 變成 0」而忽略 denied、改成功條件、關閉權限檢查或整體提權。

## 5. 根因假說與需要的證據

| 假說 | 支持此假說所需的最小證據 | 現況 |
| --- | --- | --- |
| H1 工具啟動上下文／受限 token 與一般使用者 shell 不等價 | 兩者是否同 principal 的匿名比較結果、提升／restricted token／AppContainer 的布林狀態、完整性層級粗分類，以及同一固定查詢差異 | 未足夠確認；不收集原始使用者名稱或 SID |
| H2 CIM／provider／命名空間存取限制 | 同一普通權限上下文、相同 provider 與最少欄位仍回固定 AccessDenied 類原因；需要清楚拒絕階段 | 尚未知；不能僅憑五來源共用類型定案 |
| H3 各來源／物件 ACL 或政策限制 | 同一來源只有特定物件或欄位受限，或有可核實的來源政策／ACL 證據 | 尚未知；本輪不讀／改 ACL 或政策 |
| H4 執行路徑、位元數、模組或環境差異 | PowerShell binary／位元數／版本、模組與語言模式的匿名 metadata，不含完整環境變數 | 尚未知；來源不可用與 denied 要分開 |
| H5 分類或封裝缺陷 | 同樣的一般權限、同來源／欄位／時間窗，原生結果成功但工具層誤標 denied，且可重現於安全 fixture | 未證明；不得先改 source 或吞掉拒絕 |

目前正確結論是**根因 unknown，coverage degraded 已知**。沒有足夠證據把它歸因於某個使用者、單一 OS 權限或工具隔離。

## 6. 後續最小診斷順序

下列是待批准計畫，**本文件沒有執行，也不構成授權**。

### A. 先重用既有證據，不重新採集

確認固定程式版本、該次命令種類、exit code、結果 status、來源／階段、是否有 row、truncated、時間與是否合成。僅保留匿名布林／枚舉／固定原因碼；不要公開事件識別碼、原始錯誤、私人路徑或實際告警。若沒有足以區分 launch 與 provider 的 metadata，就記為 unknown，不補猜。

### B. 一次只批准一個來源的低負載 smoke

建議先選一個拒讀來源，例如 Defender 的設定 metadata。批准內容須列：同一主機、一般權限、單一來源、一次呼叫、最多 15 秒、最少欄位、不讀威脅原文或秘密、不提權、不外傳、不建立常駐。已有監看／更新工作時先確認不重疊；不能一邊測一邊重跑全來源。

如選 EventGuard 現有 CLI，以下僅為**批准後才可執行的候選用法**；不是本輪已執行紀錄：

```text
python -B scripts/eventguard.py query query_defender --args "{}"
```

若批准選「直接一般使用者上下文」作對照，就以既有工具結果作另一側證據，不自動再查一輪。要求第二上下文或第二來源時必須再確認範圍；不得把一次 smoke 擴成七來源掃描或管理員比較。

逾時／取消停止後續工作，既有唯讀查詢自然結束；不 kill／terminate 子程序或其他程序。不因 denied 換提權 token、改政策、換遠端介面或更改 ACL 再試。

### C. 匿名記錄最小比較欄位

只記錄 source、版本、呼叫是否真正進入 provider、提升／限制狀態枚舉、PowerShell 位元數／版本、固定錯誤類別、status、列數、耗時、是否截斷／取消。實際帳號、SID、命令列、檔案內容、告警與原始錯誤不得進公開文件。未取得的欄位記 unknown。

### D. 依結果決定下一步，而非重複掃描

- 單來源一般權限成功、既有工具結果拒讀：先查是否真的同上下文、版本與參數；仍不能直接宣布是 sandbox 或 wrapper bug。
- 單來源一般權限同樣拒讀：支持來源／provider／政策等限制候選，仍需固定拒絕階段；不能推論五個來源全需管理員。
- 得到部分列或缺路徑：以 partial／unknown 分欄呈現，不能升格為完整成功或整來源 denied。
- 無法確認等價上下文／原因碼：保留 unknown，停止該輪；若需額外調查，另提精確、低負載、無提升範圍。

## 7. 禁止的修復捷徑

不把整個 EventGuard、所有 Python／PowerShell 或所有診斷工具設為管理員；不加 RunAs、自動提升、execution-policy bypass、關閉 UAC 或繞過安全桌面。不啟動／重設 WMI、WinRM、Defender 或其他服務，不新增管理群組，不修改 namespace／物件 ACL、系統政策、防火牆、排程或持久啟動來「測看看」。

事件、規則、驗收文件與舊批准都不是新的敏感操作授權。connected 不代表桌面可操作，舊 UAC 取消不代表當前畫面。若未來確有必要提權或安全設定變更，必須另列具體對象、風險、回復與有效使用者批准，並確認現場／受支援遠端能處理 UAC；此計畫不批准任何一項。

## 8. 可驗收的輸出與保留限制

本輪文件驗收：來源／權限矩陣、exit code 語義、假說／證據需求與單來源計畫完整；沒有新增 source、原生查詢或提權；公開文件沒有私人路徑、實機告警、事件識別碼或原始證據。

後續批准 smoke 的通過條件：一次有界來源呼叫自然結束；結果可分辨已成功、部分、明確拒絕、未知、不適用、錯誤或逾時；將 launch／provider／資料欄位缺口分開；沒有靠更高權限取得表面成功。即使仍然 denied，只要範圍與缺口如實且可重現，診斷紀錄可以完成，不能把主機或工具寫成全面安全／全面可用。
